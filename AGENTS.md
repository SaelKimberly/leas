# leas — Agent Guide

**leas** is a feature-rich terminal client for modern VPN and proxy protocols. Top priority: compatibility with the mainstream server backends (Xray-core, sing-box), with a first-class TUI. `v2rayN` is one reference implementation, not a parity target.

This file is auto-detected project context: commands, structure, conventions. The wiki is [`docs/INDEX.md`](docs/INDEX.md); architecture decisions are [`docs/architecture/decisions.md`](docs/architecture/decisions.md).

## Package Manager & Toolchain
- Rust 2024 workspace; `cargo` only (no JS toolchain). Toolchain declared in `rust-toolchain.toml` — the channel floats on `stable` (see the gate note below).
- Lint config: root `Cargo.toml` `[workspace.lints.clippy]`, opted in per crate. Format: `rustfmt.toml`.
- Root `[workspace.dependencies]` holds only deps used by 2+ crates or architecture-driving crates; single-crate deps live in that crate's own manifest.

## Tool Restrictions
- NEVER use `ast_edit` — it corrupts session state. Use `edit`.
- Search contents with `search`, never shell `grep`/`rg`/`awk`.
- Display files with `read`, never `cat`/`head`/`tail`/`ls`.
- Probe SQL shapes and `EXPLAIN QUERY PLAN` with the **tursodb CLI** (`~/.turso/tursodb`), never `sqlite3`: production runs the turso engine, and its planner differs (a `NOT IN` anti-join measures 5.4 s in turso against 22.7 ms for the `NOT EXISTS` form). Seed data with chunked `VALUES` statements — the CLI rejects recursive CTEs.

## Structure
- `crates/leas` — binary: `main.rs`, `alloc.rs` (the process allocator + purge policy), `state.rs` (`AppState`), `types.rs`, `ops/` (connect, ping, events, scheduler — the PER-LINK ping gate —, **job_scheduler — the job queue / one-job-at-a-time gate**, profiles, enrich, subscriptions, settings, export, stream_import, **telegram — the `t.me/s/<channel>` source that feeds the same import pipeline**, db_monitor, clipboard, native_connect, ping_native, purge, compact, geodata — geo assets + the shared routing `EngineCell`, **routing_defaults — the shipped per-country rulesets**), `ui/` (profiles, settings, logs, statistics, **details** (pane-2 `Details`: three 3:6:3 sections — Server, Link, DB aggregates), **tasks** (pane-2 `Tasks`: the progress bar + the job queue), native_activity, **sniffer** (pane-1 `Sniffer`: per-host traffic for the native session), add_server, export, status_bar, theme, widgets).
- `crates/leas-oracles` — dev-only e2e oracle crate: `build.rs` fetches the pinned xray-core / sing-box / mihomo assets (SHA-256 verified; mihomo ships a bare gzip on linux), `e2e/` builds the server/client config pairs (JSON for the first two, YAML `listeners:` for mihomo) and launches the cores, and the moved integration tests/benches live here. Excluded from `default-members`; run with `-p leas-oracles`.
- `crates/leas-hotpath` — dev benchmark crate (not in `default-members`), two bins: `leas-hotpath` (default) owns a counting `#[global_allocator]` and asserts exact allocation counts per hot path (`vless/header/*`, `vless/peel/*`, `tls13/{seal,open}/*`); `memtrace` installs `leas-memtrace` and writes per-module artifacts (workloads `header`, `connect`, `geosite`, `record`, `all`; `geosite` needs `LEAS_GEOSITE_PATH` + `LEAS_GEOSITE_CODES`, and `LEAS_MEM_TRACE_DIR` / `LEAS_MEM_TRACE_MIN_BYTES` / `LEAS_MEM_TRACE_FOLD=allocs` tune the output). It never depends on `leas`, which owns the process allocator; a path it cannot reach (a `pub(crate)` module) is not measured rather than un-privatised.
- The tracer's cost is the stack walk: `attribute` probes the ip cache while capturing, so a hit stops at the first workspace frame, and a first sight re-walks for the folded path. Keep that shape — restoring a full 32-frame capture per allocation measured 9.7 s of CPU on an 11 s boot against 6.8 s now.
- Tracing runbook: [`docs/guides/tracing.md`](docs/guides/tracing.md) — the sandbox rules, the `LEAS_MEM_TRACE_*` knobs, artifact reading and `memtrace compare`. Read it before a measurement; the traps it lists (HOME vs XDG, due subscriptions, a 64k-row DB in a PTY driver, the exit drain) each produce a confidently wrong number.
- `crates/leas-memtrace` — the memory tracer (a **default member**: its unit tests run in the normal suite). A `#[global_allocator]`-level `GlobalAlloc` that charges each allocation to the innermost workspace module: bounded `backtrace::trace` capture, a direct-mapped `ip → module` cache (one multiplicative mix, no hasher, no lock), the symbol id in an 8-byte header before the payload (so a free is an O(1) header read, never a pointer map), per-symbol atomics in a fixed slab. Artifacts are JSON + a human table + an inferno folded stack; attribution is by **module path** because release builds inline away function frames. It sees its own process only. Adapted from `leaktracer` (see the crate docs for what changed and why).
- Other crates and their responsibilities: [`docs/architecture/architecture.md`](docs/architecture/architecture.md).

## Key Conventions
- Tests live beside code (unit) or in `tests/` (integration); `thiserror` for error types, `anyhow` for propagation.
- `#![forbid(unsafe_code)]` in `leas-tls`, `leas-native` and `leas-oracles`; crypto standard is `ring` (plus `x25519-dalek`, RustCrypto `ml-kem`, `ml-dsa` — the last verify-only, for REALITY's certificate extension). Socket options stay on `socket2`'s SAFE surface for the same reason; `SO_MARK`/`SO_BINDTODEVICE`/`TCP_CONGESTION` need an ADR. `TCP_MAXSEG` and `TCP_QUICKACK` do have safe setters and are used: `path_mss.rs` advertises 1360 (1220 after three handshake stalls with no success between) and the dial applies it to an UNCONNECTED `TcpSocket`, because the MSS only matters in the SYN. Process signals in `leas-oracles` go through `rustix` (a `cfg(unix)` dependency) because `libc::kill` is `unsafe`. Consult `docs/reference/crypto-dependencies.md` before adding a primitive.
- All DB access is async on `Database`; the typed path is the default, raw SQL needs a recorded cause in `docs/reference/database-manual-sql.md`.
- A database that fails to open is NEVER deleted: `Database::open` propagates the error and leaves the file untouched (a second instance opening a live file used to wipe it). The only wipe left is the explicit `IncompatibleSchema` verdict.
- TRACE is off process-wide: `crates/leas/src/logging.rs::cap_trace` appends an outermost `LevelFilter::DEBUG`, because `turso_core` takes its traced VDBE loop (one explain `String` per opcode, `vdbe/mod.rs:2598`) when `tracing::enabled!(TRACE)` answers true — per-layer `EnvFilter` directives never reach that gate. Removing it cost 2 574 862 → 103 659 allocations per boot (bucket 2 455 961 → 2 934) and 6.29 → 0.50 s of traced-boot CPU; `tests/tracing_level_gate.rs` is the guard, and `docs/aegis/specs/2026-11-16-boot-allocation-burst-design.md` is the record.
- The process allocator is owned by the binary: `crates/leas/src/alloc.rs` installs `#[global_allocator]` (mimalloc 3.6.2 via `rustfs-mimalloc` 0.7.4, `cc`-built on every target so windows-gnu needs no CMake), `configure()` at startup applies the Linux retention tuning (`allow_thp=0`, `page_full_retain=0`, `page_max_reclaim=0`, `page_cross_thread_max_reclaim=0`, `generic_collect=512`; indices pinned by a readback test), and `release_freed_heap()` runs at job boundaries. NEVER override `purge_delay` to 0 on 3.x — it turns every free into a purge (~1.7–3x slower burst). The tuning is Linux-specific: Windows defaults already measured better, and 3.6's Linux defaults cost ~130 MB settled on a feed-wide batch. Two compile-time switches sit on top: `std-alloc` installs `System` instead (external profilers only see per-allocation events through it; mimalloc hides them), and `mem-trace` (implies `std-alloc`) installs `leas-memtrace` and writes `target/mem-trace/` artifacts at each `alloc::job_boundary` label. Only one `#[global_allocator]` may exist, so these are mutually exclusive builds, not runtime switches. `leas-db` must NOT enable turso's `mimalloc` feature — a library-owned allocator cannot be configured, measured or swapped.
- The schema cursor is `PRAGMA user_version` (`crate::schema`): a supported older version MIGRATES, an unknown one wipes. A real DDL change adds a `schema::steps` entry and bumps `SCHEMA_VERSION` (the step and the cursor stamp share one transaction); a change that is NOT DDL never bumps it — an identity re-key is a DATA step behind an `app_meta` marker. `app_meta.capability_version` is the same kind of DATA step: `Database::clear_stale_capability_verdicts` (called from `main` with `leas_native::capability::SUPPORT_REVISION`) clears only the persisted `not testable by the native engine:` verdicts, so a native-support upgrade re-opens those rows once.
- Routing rules are per-country rulesets (`ru`/`cn`/`ir`) with exactly one active: the shipped `default` table lives in `crates/leas/src/ops/routing_defaults.rs`, `custom` rows carry `routing_rules.ruleset` (`NULL` = a pre-ruleset row, custom under every country). The geo dataset only gates compatibility: an unservable `geosite:`/`geoip:` code disables its row and is skipped at build (`GeoInventory` + `incompatibility`), never a build failure; `geoip:<cc>` falls back to the GeoLite2 mmdb for two-letter codes only.
- A config that NO shipped codec can dial is refused at ingestion (ADR 0018 D-C): an `ss` "method" outside `NATIVE_SS_METHODS` (`leas-proto`, pinned to the native codec by a test), a non-empty VLESS `flow` with no TLS/REALITY layer (`flow=none` parses as absent), or a transport `Host`/`:authority` outside Go's `ValidHostHeader` set (`proto_spec::transport_host_unrepresentable`, read through the one `TransportConfig::host` list; sub-delims such as `!$&'()*+,;=~` are representable, `@` is not). The ingest gate applies `validate_ss_config`/`validate_vless_shape`/`validate_host`; `Database::open`'s one-time `invalid_shapes_purged` step (marker version 2) wraps the same flow/SS/host predicates and gives stored rows the `config_invalid` verdict. Upstream removal alone is never a ground to retire a variant (ADR 0018).
- Every HTTP request target is built through `transport::request_target`: a space, `#`, control or non-ASCII byte becomes `%XX` (Go `EscapedPath` set; a valid `%HH` is preserved, never double-encoded). The WS plugin twin (`v2ray/ws.rs`) uses it too. The xhttp h2 arm sends an absolute URI (`https://{host}{path}`): `h2` derives `:authority` from the URI only, so an origin-form target leaves it empty and a CDN answers 421; h1 keeps origin-form and h3 rewrites from `path_and_query`. An empty transport `host=` means unset — `transport::host_or` falls back to the endpoint at every Host consumer; rejecting empty would drop rows the references dial.
- A real probe observes a failing link TWICE (sequential, one confirm; `probe_attempts`), and only a CONFIRMED failure samples the stability ring — a single timeout never demotes a link. The second observation's target is the Cloudflare trace when the first died at the destination (it also yields the exit IP, so that success needs no second tunnel); a dial/transport failure is re-observed on the same target. `failure_pair` (class + `transport_failed` + evidence) persists `error_stage`/`error_cause` beside the marker (schema 22, pair CHECK) — never prose. The pair reaches SQLite only through the shared raw link writer (`LINK_UPSERT_PREFIX` + `link_values_sql` + the RESULT conflict set in `leas-db/src/database.rs`); a struct-level test does NOT prove persistence — `link_upsert_persists_the_failure_pair` is the seam test, and the pair columns carry no value CHECK, so a wrong storage spelling is caught only by the typed read-back. `error_kind='name'` is legacy read-only (no writer; DNS failures land as `fast`). A data-carrying success (Real Test, Speed Test) is also an APPROVAL: it clears the verdict and stamps `last_seen_at` through `LinkGroups::SEEN` (monotone `MAX`), the clock `band` (Active/Purgatory) and `purge_expired` read — which is what lets `Real Test (Purgatory)` resurrect an aged or purged row (`PlanSource::Purgatory`, purged links included; feed sweeps still skip them, ADR 0006 D8). A new `LinkGroups` bit must reach `GROUP_FLAGS` and `merge_group` in `leas-db/src/write_behind.rs` and the bucket bound in `apply_link_patches_tx`, or `stage` drops it and nothing is written while every producer-side and SQL-side test still passes; `link_flush_writes_the_seen_stamp_and_no_other_column` is that seam test.
- `leas-hakari` is generated — regenerate with `cargo hakari` after any `Cargo.lock` change; never edit it by hand.
- On a TCP tunnel connect, the protocol request header is withheld by `protocol::first_flight::HeaderFirst` and leaves in the same carrier write as the first payload or first mux frame (Vision joins its camouflage frame to the first padded frame); a read flushes the header before handing up read data. The header is built with `encode_request_into` into the buffer `HeaderFirst` owns, reserved at `HEADER_RESERVE` = 96 bytes (longest header ≈56 + the 21-byte camouflage frame), and the Vision addons are a `&'static [u8]` constant — one allocation per Vision connect, no addon `Vec`. Eagerly writing a header on a TCP connect is a regression: it recreates the small telltale record. The UDP connect paths (`connect_udp_plain`, trojan `connect_udp`, the SS datagram streams) still write theirs eagerly — declared out of scope, because a datagram frame has a different lifetime and the small-packet tell is a TCP-connect property.
- The relay starts each direction at 16 KiB and promotes to 64 KiB after a read fills the small buffer, **after** the write that consumed it (`inbound/outbound.rs`). Promoting earlier would swap the buffer and discard the bytes just read. Relay buffers come from a bounded pool (`POOL_CAP` 64 per size class = 2 MiB; `RelayBuf` returns on drop, promotion swaps size classes) whose free lists are pre-reserved at first use — the return path runs from `Drop`, and allocating while unwinding aborts. The relay's idle cap is `RELAY_IDLE` (90 s); the old 30 s `TUNNEL_READ` was deleted with it, and the CONNECT budget is the separate `CONNECT` constant (15 s). The stamp is shared by both directions, so only a fully silent tunnel fires it, and 30 s reaped healthy Discord-gateway sessions (heartbeat 41.25 s) and long-polls; 60 s still reaped Google push (`mtalk.google.com:5228`), Telegram web and GitHub-alive long-polls (2026-11-24 audit: 2 985 reaps, 947.8 MB carried). Raising it is not a memory trade — no buffer changes.
- DNS resolution splits **queue wait** from the resolver answer: `acquire_permit` waits at most `DNS_QUEUE_WAIT` (5 s) for a `RESOLVE_SEM` permit and a starved lookup is `Permit::Starved` — it must release its waiters with NO `mark_dns_failure` and NO `resolved_at` stamp (the stamp pins the host for `dns_cache_ttl_secs`). Report time is `DNS_REPORT_BUDGET` (queue + lookup, 13 s) and every budget that must outlast a resolution — the batch's deferral accounting and `MIN_DNS_DEFER_SECS` (15 s) — reads that constant, never `DNS_LOOKUP_TIMEOUT` alone. The 2026-11-19/20 run recorded 12 093 hosts as DNS failures in six seconds with a single 8 s deadline around both; the assessment in `docs/research/2026-11-20-log-review-real-test.md`.
- Every SOCKS5 **server** frame (method selection, RFC 1929 auth status, CONNECT reply) leaves in ONE `write_all` (`inbound/socks5.rs`): the accepted socket has `TCP_NODELAY`, so per-field `write_u8` calls become separate segments, and apt's SOCKS5h client reads with a non-blocking fd where `EAGAIN` mid-frame is a hard failure (`Reading the greet back from SOCKS proxy ... failed`, errno 11). `server_frames_leave_in_one_write_each` pins it.
- **`encryption` is validated at ingestion, not at dial.** `leas-proto` owns one normaliser per owner: VLESS restores `none`/`auto`/`none`+junk to absent and accepts only a valid `mlkem768x25519plus`, whose full validity (grammar, decoded keys, padding bounds) also lives there and is consumed by the native handshake; `VlessConfig::validate` re-runs it for stored rows and `capability` refuses by name. Every other share-link parser rejects any `encryption` presence, and the fallback chain stops on `InvalidConf`, so a mis-schemed body is dropped instead of healing into Trojan/Hysteria (both accept any userinfo as a credential). Trojan-Go's `ss;<method>:<password>` layer is a **bare** classic-AEAD stream (`protocol/ss/stream.rs::wrap_bare`, `first: None`, no SS target-address header) between the carrier and the Trojan header; `trojan-go://` is the scheme, `type=original`→TCP, `plugin=` is refused, the method is in the sig identity and the password in the credential stream, and xray/sing-box/Clash builders refuse a layered row. A marker-gated DATA step (`app_meta.vless_encryption_normalized`, no cursor bump) re-keys stored restored rows on open.
- Mux is pooled, not per-leg: `crates/leas-native/src/mux_pool.rs` owns the carrier pool (key = wire-visible identity incl. VLESS `encryption` / SS cipher and the profile wire; live slots reserved under the entries lock; a 1 s-bounded build gate coalesces a cold burst but never serializes a failing one; an idle sweeper closes zero-live carriers after 16 s; a failed open evicts and retries once). Default-on applies to VLESS rows without a `flow` and not on `xhttp`; a row's `muxtype`/`mux=false` always wins (`VlessMux::Named` carries the wire, cap from `mux`/`muxConcurrency`). An sbox carrier is the proxy request to `sp.mux.sing-box.arpa:444` first, then the versioned handshake (padding is a Version1 handshake property) over `HeaderFirst`+`PaddingConn`, then h2mux/smux/yamux. `transport/sbox/` is hand-written to the pinned Go references — no crates; `xhttp` h2 connections are pooled first-hop only (`LinkContext::direct_hop`). Oracle evidence: `tests/vless.rs` mux rows (one carrier per N SOCKS legs via a counting TCP proxy); mihomo's h2mux fork is a recorded interop gap (`#[ignore]`d with the reason). UDP pools on the same object: `mux_pool::effective_udp_mux` is `effective_mux` OR the `xtls-rprx-vision-udp443` flow (the flow *is* the XUDP declaration), and it must stay the single predicate `protocol::vless::udp_uses_mux` also feeds `connect_udp` — when the two disagreed, a udp443 row was dialed as XUDP but built as a raw leg (`case_38_vision_udp443` red on both cores until 2026-11-20). A non-pooled UDP leg carries `PacketMode::Raw` and is destination-locked. The carrier writer (`transport/mux.rs::writer_loop`) drains every frame already queued into one write capped at 16 KiB (`WRITE_BATCH`) with a reused buffer — one syscall and one or two TLS records per burst, no per-frame allocation; only `try_recv` is used, so a lone interactive frame never waits for company.
- A probe batch's live state is bounded by construction, because a feed-wide Real Test otherwise holds one chain, one parsed protocol config and one quinn endpoint per planned link. `ops::ping`: `dispatch_fast_link` takes the ONE probe permit (`real_ping_concurrency`) **before** spawning a chain for BOTH batch kinds, and the real half reuses that permit rather than acquiring a second (the fast-only path always did this; the real phase used to spawn every chain first — measured 213 MiB live). `SiblingGate` keeps group verdicts and held siblings under one lock so a group that settles before its page published its siblings still releases them (the throttle makes that ordering reachable; without it `main.done` is never counted and the batch hangs). The parsed-protocol memo is capped at `PROTOCOL_CACHE_CAP` (a feed is nearly one unique config per link; unbounded it held 175 MiB), and finished chain `JoinHandle`s are pruned every 256 settles (a completed task's allocation lives until its handle drops). Numbers and labs: `docs/research/2026-11-23-live-memory-audit.md`.
- QUIC client endpoints are SHARED per address family (`transport::quic::client_endpoint`, `LazyLock`, production only; test/e2e builds bind per dial because each harness case has its own runtime). A fresh `quinn::Endpoint` allocates a 188 KiB receive buffer (`max_udp_payload_size × GRO segments × BATCH_SIZE`), and a feed-wide probe dials hundreds per second — per-dial endpoints held 541 MiB in `transport::quic`. One endpoint multiplexes every connection. The QUIC `rustls::ClientConfig` is cached per (trust mode, ALPN); an h3 open/transport/auth FAILURE must close the connection explicitly, because the driver task holds the endpoint until `poll_close` resolves (otherwise quinn's 300 s idle timeout). Obfuscated hysteria2 still binds per dial and reports `max_receive_segments = 1`.
- A streaming import ends with `alloc::job_boundary("import")` (`ops/stream_import.rs`): the parse/write-behind burst is the app's other burst-shaped workload, and an idle session never allocates enough to fire mimalloc's purge timer. `release_freed_heap` is a FORCED `mi_collect(true)`; there is no idle poll.
- One subscription network failure is ONE persisted error line: the pipeline's `DB upsert INCOMPLETE` warn and the `Subscription update failed` event own the text (`ended_early` carries it), so neither the fetch path nor `http_client`'s build failure may log its own `tracing::error!` (2026-11-24 audit G8). A body-read failure names its source as `scheme://host[:port]/path` (query/fragment dropped — a feed URL can carry a token) and the bytes served, because the source identity was the missing half of the 2026-11-24 decode-failure evidence (G7).
- Shadowsocks-2022 multi-user rows (`iPSK1:…:uPSK`) are served natively: `ss/eih.rs` owns the identity headers (TCP identity-subkey derivation, UDP `hash XOR session_id‖packet_id` form), `method::password_chain` is the only password→keys parser, and `2022-blake3-chacha20-poly1305` refuses a list (no AES block; xray and sing-box agree). Response packets never carry EIH.
- `zeroize` on owned key buffers, and the `zeroize` FEATURE must stay listed on every crypto dep that touches keys — re-check after any crypto dep edit.
- In-memory geo/matcher strings are `CompactString` (`GeoDomains`, `DomainRulesSpec`, `CompiledDomain`'s sets): most domains fit inline (≤24 B on 64-bit, 88 % of a typical `geosite.dat`), so they never reach the allocator, and `lower_one` skips the lowercase copy when a value is already lowercase. DB **model** columns stay `String` — toasty 0.11 implements its `Field` trait for a closed primitive set (`String`, `Uuid`, `bool`, `isize`, `usize`, `Vec<u8>`) and the orphan rule forbids extending it for a foreign type. A geo dataset is parsed **once per build** (`GeoCompiler::preload`) and the cache is moved into the rules (`take_site`), never cloned per rule.
- `terminal.draw` allocates nothing per frame in the Profiles pane and the shell chrome: labels/log text are borrowed, short values go through `ui::FmtBuf` (stack `format_args!`, truncates at a char boundary), row heights come from a closure instead of a collected `Vec`, and the grid header is cached on `AppState` keyed by `(pane width, header style)`. The display-row cache and the header cache both must be invalidated when `state.theme` changes (`ops/settings.rs` marks the row dirty bits). Logs/Sources still rebuild their column `Vec` per frame — measured, not yet changed. Measurement recipe and numbers: `docs/research/2026-11-13-allocation-profile.md` §Render path.
- A test earns its place by discriminating a plausible consumer-visible bug: behaviour, boundary, invariant, state transition, precedence, error class, wire bytes, ordering, golden/parity. Tautologies (asserting a literal the test itself defined), source-text, mock echoes, bare not-throw, non-empty/length-grew/is_some-only and same-path duplicates do not.
- Tests identical modulo literals are ONE `#[rstest]` table with named `#[case::…]` rows — never N near-identical `#[test]` fns. Every `#[case]`-supplied parameter must carry `#[case]` (a missing one makes rstest report "Wrong case signature" and silently drop the whole fn).
- Perf labs and planner/timing probes are not tests: they live behind the crate's `perf-lab` feature as `#[cfg(all(test, feature = "perf-lab"))]` (the `test` term is required — a lab that drives test-only helpers and `tempfile` cannot compile in the lib unit), stay `#[ignore]`d, and print tables. Run one with `cargo nextest run -p <crate> --features perf-lab --run-ignored all <name>`.
- Every hand-written crate opts into `[lints] workspace = true`. A crate without it is silently outside `pedantic`+`nursery`, generated code included (prost's `PartialEq`-without-`Eq` needs a scoped allow at the `include_proto!`).
- `cargo nextest run` is the suite (default members; the dev-only `leas-oracles` is skipped). `--all-features` is clippy's surface, with `--exclude leas-oracles`. The real-core e2e rows live in `leas-oracles`: `cargo nextest run -p leas-oracles`; its `build.rs` fetches the pinned cores (override `$LEAS_CORE_BIN_DIR`, or `LEAS_ORACLES_SKIP_DOWNLOAD=1` for a compile check). The pins track each project's **newest release tag** (sing-box may be a pre-release); bumping them is `crates/leas-oracles/src/pins.rs` plus `just oracles-pins <xray> <singbox> <mihomo>`, then triage the reds — an upstream default change can red a whole transport (a `freedom` egress policy, a key-share requirement, a renamed config type), so read the core's own log (`LEAS_CORE_LOG=1`) before assuming the client is wrong. A red row whose scenario no pinned server can serve is a wrong expectation, not a client bug: check the upstream config surface first, then delete or `#[ignore]` the row with the upstream evidence in the reason, and move the client claim to a hermetic test.
- The toolchain floats on `stable`; a new stable release can promote a lint and redden the gate. That is now detected rather than silent: `stable-drift.yml` re-runs the `code` gate weekly against the newest stable, so drift surfaces within a week, and `just quality-gate code` after a toolchain bump stays the local check. CI (`.github/workflows/`, added 2026-10-13): `code-linux` runs the `code` gate plus a release build inside an `ubuntu:22.04` container (the `GLIBC_2.35` floor), `code-windows` runs the `code` gate on `windows-2022`, `deps` runs single-homed on the host.
