# Plan — `stab_bin`: link stability in the ordering law

Date: 2026-10-09
Status: EXECUTED 2026-10-09 — all ten tasks landed; deviations recorded under "Execution notes" at the end.
Spec: `docs/aegis/specs/2026-10-09-stab-bin-design.md` (approved for planning)
Source draft: `STAB_BIN.md` (superseded)
Aegis route: `writing-plans`. Execution route: **inline** — the tasks share one
law (`endpoint_rank.rs`), one word of shared state (`LinkGroups`), and one
schema; parallel owners would mean two writers on the same files.

## Goal

Record each link's last N real-probe outcomes as a ring, derive an 8-level
`stab_bin` from it, insert that term into both ordering keys, and materialize a
per-endpoint `rank_proven` so `Successful` means "has worked, repeatedly"
rather than "last probe succeeded".

## Architecture

One law, three layers, two representations that must agree:

- **Rust (authoritative)** — `RankLink::key` becomes
  `(bin, stab_bin, u64::MAX - weight, -seen_secs, protocol_id)`; `compute_rank`
  keeps one `.min()` and gains two derived outputs (`stab`, `proven`).
- **SQL (mirror)** — `ORDER BY band, rank_bin, rank_stab, rank_weight DESC, …`
  served by one covering index with `rank_proven` trailing.

Membership is a **separate stored fact** (`rank_proven`), not a key term: an
endpoint whose representative is an untested sibling (bin 12) or a failed link
(13) is still proven when another live link's ring holds a success.

Owners, unchanged: the law stays in `endpoint_rank.rs`, the page and the scope
predicates stay in `profiles_query.rs`, the producers stay in
`ops/ping.rs`/`ops/events.rs`, the panel stays in `ui/profiles.rs`. **No new
owner file.** The ring codec lives beside `stab_bin` in `endpoint_rank.rs`
because they share one bit layout.

## Tech Stack

Rust 2024, `toasty` 0.11 + the crate's own turso driver, `cargo-nextest`,
`just quality-gate`. Planner assertions run on turso in
`crates/xray-tui-db/tests/turso_planner.rs`.

## Compatibility Boundary

- **No schema cursor bump.** `SCHEMA_VERSION` stays 18. The four columns are
  **typed model fields** (`ProfileStats::stab_mask/stab_len`,
  `EndpointRank::rank_stab/rank_proven`) *plus* `ALTER TABLE` entries in
  `ddl.rs` for databases that already exist — `push_schema` runs only at cursor
  0, so a declared field costs no bump and no wipe.
- **Identity is untouched.** No `write_identity` change, no `IDENTITY_VERSION`
  change: stability lives on links, never on config identity. No re-key, no
  stale-uid hazard, no duplicate `Protocol` rows.
- **An upgraded feed keeps its rows** and its previously-successful endpoints
  stay in `Successful` — but only because of the T3 seed (a link with
  `latency='real'` gets `mask=1, len=1`). Without it every pre-upgrade success
  is invisible to `rank_proven` and falls out of all four scoped menus.
- **Measurement is untouched**: `latency`/`error`/`purge_reason` keep their
  meaning. `rank_bin` still reports the representative's LAST outcome — only
  the key gains a term and the scopes gain a predicate.
- **Behaviour-visible**: the Successful/New/Failed menus change which endpoints
  they select (R1), and the Test page order changes inside a bin.

## Change Necessity

No config or docs-only path exists: the ring must be persisted per link, the
law must gain a term, and `proven` must be materialized where SQL can filter
it. Minimum code boundary = one pure module-worth of codec+quantizer in
`endpoint_rank.rs`, four columns, one index, one group bit, the producers, and
the panel column. Nothing here is reachable by configuration.

## TDD Route

`auto` → **strict**. Authority: schema/persistence change + a shared ordering
contract read by both SQL and Rust + producer/consumer (the probe path writes
the ring, the rank refresh and the panel read it) + a migration-adjacent seed.
Posture: each task starts with a failing test that pins its Acceptance, then
the minimum change, then the task's command. The workspace-wide run happens
once at T10.

Precondition (implementation-owned, decided in T1): the exact rate boundaries
and whether `KEY_INPUTS_VERSION` is a new constant or `WEIGHT_VERSION` is
bumped.

## Ripple Signal Triage

Fires: schema/persistence, shared core ordering contract, both producer
(`ops/ping.rs`) and consumer (`profiles_query.rs`, `ui/profiles.rs`), and a
derived-state recomputation path.

- **Canonical owner**: the law is `endpoint_rank.rs` only. `RankLink::key` stays
  the single implementation; `EndpointRow::link_test_key` keeps delegating.
- **Downstream consumers**: the page/walk/count predicate builders (all in
  `profiles_query.rs`, shared so they cannot drift), the panel, the batch
  scopes, `profiles_anchor`.
- **Source of truth**: the ring is the only stability fact; `rank_proven` and
  `rank_stab` are derived and rebuilt by the refresh. No second store.
- **Retirement**: the v18 index name is dropped; the stale "a model field needs
  a tag bump" comments in `endpoint_rank.rs`/`ddl.rs` are corrected because they
  are now wrong (T2).

## Tasks

### T1 — the ring codec and `stab_bin` (pure)

**Files:** `crates/xray-tui-db/src/endpoint_rank.rs` (new section + tests).

**Change:** `pub const STAB_WINDOW: u8 = 16`, `STAB_WARMUP: u8 = 4`,
`STAB_NEUTRAL: u8 = 4`; `pub const fn stab_bin(mask: u64, len: u8) -> u8` (the
percent table from spec §5.1, `len < STAB_WARMUP` → neutral);
`pub const fn append_sample(mask: u64, len: u8, ok: bool) -> (u64, u8)` with the
two distinct arms — `len < 16`: `mask |= ok << len; len += 1`;
`len == 16`: `mask = (mask >> 1) | (ok << 15)`.

**RED first:** a threshold table test over every `(successes, len)` pair
(8 boundaries + warm-up + empty); monotonicity in successes; the
`bits [len,64) are zero` invariant after an arbitrary op sequence; eviction
(oldest out) at `len` 0/15/16; 20 successes then 16 failures → `count_ones() == 0`.

**Acceptance:** the table matches spec §5.1 exactly; the partial and full append
are distinct and both correct; `count_ones()` equals successes at every length.

**Command:** `cargo nextest run -p xray-tui-db stab`

### T4 — the law: `RankLink`, `compute_rank`, `RankRow`

**Files:** `crates/xray-tui-db/src/endpoint_rank.rs`.

**Change:** `RankLink` gains `stab: u8` (from `stab_bin(mask, len)`) and
`proven: bool` (`mask != 0`, i.e. any `1` in the window); `RankLink::new`
derives both; `key()` inserts `self.stab` after the bin; `compute_rank` sets the
typed `EndpointRank` fields `rank.stab` / `rank.proven` — `stab` from the
minimum-keyed link, `proven` ORed over **live unpurged** links (they are typed
model fields per T2, so they need no parallel `RankRow` field; only the raw
`weight` does). `RANK_COLUMNS` and the `VALUES` tuple gain `rank_stab`,
`rank_proven`; `refresh`'s link statement gains `ps.stab_mask`, `ps.stab_len`;
`rank_of_row` and `backfill_all` populate them (`backfill_all` needs no
projection change — the fields are typed).

**RED first:** link-key order — two links with equal bin/weight, different
`stab_bin`, order by stability; a proven endpoint whose min link is bin 12 or 13
still yields `proven = 1`; a purged-only link contributes no proven; a
full-failure ring yields `proven = 0` after enough samples; `RANK_COLUMNS`
round-trip — refresh a row twice and `rank_proven` does not reset to 0.

**Acceptance:** the key is `(bin, stab, ¬weight, -seen, protocol_id)` and
`EndpointRow::link_test_key` still delegates to it (parity test); an endpoint
with a live proven link reports `rank_proven = 1` at any bin.

**Command:** `cargo nextest run -p xray-tui-db endpoint_rank`

## Risks

- **The seed is the migration.** If T3's gate misfires (seeds on every open, or
  never), either counters double or the pre-upgrade Successful set vanishes.
  Covered by the "second open does not re-seed" test.
- **`INSERT OR REPLACE` reset.** Omitting the two new columns from
  `RANK_COLUMNS` silently resets `rank_proven` to 0 with no error. T4 pins it.
- **Staged-read race.** `get`+`push` is not atomic; the scheduler's one-mutex
  gate covers link transitions today. T7 pins the single-ping path.
- **Scope orphans.** Bins 6–11 (fast success only) match no scope. Pre-existing,
  documented in T9, not silently carried.
- **Order change.** A 50%-flaky link now sorts below an untested one (neutral 4).
  Deliberate (D10); recorded in §3.1.

- Deliberately retained: `PlanScope::bins()` for `All`; the two-key split; the

## Execution notes

All ten tasks landed. Deviations from the plan as written, each for a reason found
during execution:

1. **T2: typed model fields, not raw columns.** `ProfileStats::stab_mask`/
   `stab_len` and `EndpointRank::stab`/`proven` are declared fields (the model is
   what `decode_projected_link` builds, and the panel reads them there). The
   `ALTER TABLE` entries stay, for databases that already exist — `push_schema`
   runs only at cursor 0, so a declared field costs no cursor bump and no wipe.
   The stale "a model field needs a tag bump" comments in `endpoint_rank.rs` and
   `ddl.rs` are corrected. `rank_weight` remains the only raw column.
2. **T3: the seed also clears the key-input stamp.** The plan did not say so,
   but without it the rank keys are never recomputed: the stamp is already
   current, so `ensure_in` takes the no-op path and the seeded rings never reach
   `rank_proven`. `seed_stability` therefore deletes `rank_weight_meta` after the
   UPDATE, which is the existing recompute trigger.
3. **T4: `proven` is also gated on `!dns_unresolved`.** Found by the T5 scope
   test: an unresolved DNS host with a stored real measurement was reporting
   `proven = 1`, so it left the old `Successful` set (its links collapse to bin
   15) but entered the new one. The bin list excluded it structurally; under the
   proven-first partition the exclusion has to be stated.

   > **Corrected 2026-10-22 (ADR 0003 amendment, `STAB_VERSION` 2 → 3):** the gate is
   > `!dns_unresolved || measured_any` — a MEASURED link is not "unresolved". The probe dials
   > the DNS name and the OS resolves it, WITHOUT persisting the resolution, so a DNS endpoint
   > the probe reached has an empty address set AND a measurement; the old reading filed it
   > below every real-error band, so a working server sorted below the failures. The same
   > correction applies to the band law itself: bin 15 is for the links that were NEVER
   > measured. `plan_scopes_select_by_materialized_tier`'s fixture (e6) became genuinely
   > unmeasured for this reason, and
   > `a_measured_dns_link_keeps_its_real_band` /
   > `a_fast_measured_dns_link_admits_its_proven_sibling` cover the measured arms.
4. **T5: `PlanScope::bins()` is retired entirely**, not kept for `All`. With
   proven membership it can express no scope, so the accessor was dead weight;
   `PlanScope::predicate()` replaces it.
5. **T6: `link_patch_conflict_sql` takes a `LinkGroups`**, not four booleans
   (clippy's `fn_params_excessive_bools`), and the patch bucketing loops a 4-bit
   `bucket` rather than listing eight tuples.
6. **T7: a second producer split the plan did not anticipate.** The batch and the
   events handler both stage a result, so sampling in both would count every
   batch probe twice. The batch owns the sample for its links (its rows are
   off-page in the handler, which holds only the loaded page); the handler
   samples only single pings, gated on `state.batch_progress.is_none()`. A single
   ping whose result lands while a batch runs MISSES its sample — a miss, never a
   double count — which is the safe direction. The untestable marker is excluded
   by its own prefix check, so the capability gate cannot accrue attempts.
7. **T8: the stability column is the panel's 12th**, at offset 115, leaving every
   existing sub-row offset untouched.
8. **T10: timings were NOT re-measured** — no real feed was available. The plans
   are asserted (and the assertion has teeth: a misplaced `rank_proven` fails it
   with `USE SORTER FOR ORDER BY`), and `docs/ordering_law.md` §8.1 says plainly
   that the page-fetch numbers above predate this change. The second index was
   NOT added, as the plan allowed.
