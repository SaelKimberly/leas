# DRY normalization: dedupe semantically identical entities across workspace

## Context

User asks to detect semantically identical entities across the leas workspace and normalize the codebase for DRY. Three read-only audits (proto, native+tls, app+db) found ~4,700 duplicated LOC in 30+ clusters — per-protocol copy-paste families, twin decoders split across crates, repeated TUI/ops skeletons. This plan consolidates them into shared helpers/macros/modules while pinning behavior with existing tests. Exclusions (deliberate): machine-generated code (`leas-tls/src/fingerprints/catalog/catalog_data.rs` via gen.py, `tls/src/profiles/generated/*` via gen_specs.py), `leas-hakari` (generated feature unification), `thirdparty/*` (read-only references), `native/src/crypto/b3.rs` (justified single-site BLAKE3 reimplementation), and xray-vs-singbox config builders' mirrored JSON dialects (intentional port; shared atoms already factored).

## Approach

Execute as four waves. Within a wave steps are independent; waves are sequential — each must leave `cargo test -p <wave-crates>` green before next starts.

### Wave 1 — proto crate (~2.5k LOC)

1. **Delete legacy `ProtoSpec` bridge trait + its 20 impl blocks.** In `crates/leas-proto/src/proto_spec/mod.rs` remove the `pub trait ProtoSpec` definition (~lines 296-361), the 20 per-config `impl ProtoSpec for XConfig` blocks (one per config file; find exact set with `grep -rn "impl ProtoSpec" crates/leas-proto/src`), and the ProtoSpec-bridging inherent methods on `ProtocolConfig` that exist only to serve it (`schema`, `host`, `port`, `remarks`, `country_flags`, `to_json_config`, `reconstruct`, `try_from_clash` — keep everything routed through `dispatch!` that has real callers; verify each with `grep`). Migrate every external callsite found by `grep -rn "ProtoSpec\b\|::try_parse(\|\.reconstruct()\b\|\.schema()\|\.country_flags()\|\.security()\|\.transport_type()" crates/leas/src crates/leas-config/src crates/leas-core/src crates/leas-native/src --include='*.rs' | grep -v _proto | grep -v 'fn '`. Known callers to migrate: `crates/leas/src/ops/enrich.rs:23-32` (`extract_sni` uses trait `.security()` on `config.get().0` — replace with typed field access mirroring line 29's fallback: `protocol.security.sni.clone()` path already exists, so make the loaded-config branch read `SecurityConfig::sni()` directly off the typed struct without the trait import); `crates/leas/src/lib.rs:27` and `crates/leas/src/state.rs:23` (imports only — delete `ProtoSpec` from use lists); `crates/leas-config/src/import_export.rs:675`, `crates/leas-config/src/subscription.rs:10`, `crates/leas-native/src/e2e/case.rs:552`, `crates/leas-native/src/e2e/config.rs:794` (test imports — switch to direct `*_proto` methods). Keep the private `ProtoIdentity` supertrait and its dispatch impls — identity hashing is live.
2. **Add `singbox_out_base()` + shared inject helpers** in `crates/leas-proto/src/proto_spec/common.rs`: `pub(crate) fn singbox_out_base(kind_tag: &'static str, endpoint: &EndpointEssentials) -> serde_json::Value` returning `{tag:"proxy", type:<kind>, server, server_port}`; signature mirrors existing `to_singbox_tls_or_default` at common.rs:1034. Migrate all 14 `inject_singbox` bodies (tuic.rs:431 is canonical example) to call it then attach protocol fields; also replace the `let Some(ep) = endpoint else { return Err(SupportError::MissingField("server", "<proto>")) }` unwrap idiom with `fn singbox_endpoint(endpoint: Option<&EndpointEssentials>) -> Result<&EndpointEssentials, SupportError>` taking the kind tag (51 MissingField sites crate-wide are covered by this + step 1). No behavior change: same JSON keys, same error literals (`SupportError::MissingField("server", "tuic")` etc.) — tests asserting these error shapes stay green.
3. **Add URL-serializer builder** in common.rs: `pub(crate) struct ShareUrlCtx { parts: Vec<String> }` with `hostport(endpoint)->String` (IPv6-bracket logic, replaces 13 byte-identical `if contains(':')` blocks), `push_opt(key, Option<&str>)` emitting `k=<urlencoding::encode(v)>` when Some and not `should_skip_endpoint_param(host, v)` for host-bearing keys, `finish_query()->String` producing `""` or `"?a=b&c=d"`, `fragment(Option<&str>)->String`. Replace query assembly in all 13 `reconstruct_proto` impls (trojan.rs:211 is the heaviest template; ssh/tor/tailscale error stubs untouched). Existing round-trip parse/reconstruct tests per protocol file are the pin.
4. **Collapse reconstruct-side duplication**: extract `security_query_pairs(&SecurityConfig, endpoint_host) -> Vec<(String,String)>` (sni/alpn/fp/insecure triples ×4 + reality pbk/sid/spx ×2, feeding ShareUrlCtx) and `transport_host_param(&TransportConfig) -> Option<&str>` (the Ws/Grpc/Http/HttpUpgrade/XHttp `cfg.host|authority` match ×7) into common.rs; wire into step 3's migration so each `reconstruct_proto` shrinks to userinfo scheme + table of pushes. Add `fn parsed_proto(proto_kind, config_type, core_type, config, endpoints) -> ParsedProto` free ctor in `proto_spec/mod.rs` replacing the 24 near-identical `Ok(ParsedProto{...})` tails, plus `remarks_from_name(Option<&str>) -> Option<String>` replacing the 17 copies of the `""=>None` match.
5. **Parse-prelude helper**: add `split_userinfo_hostport(raw) -> Result<(Option<String>, &str parsed_host, u16 port), ParseError>` + `endpoint_from_spec(parsed_host, parsed_port, ports_iter) -> EndpointEssentials` in `utils.rs`, migrating the 12 try_parse preludes (tuic.rs:110-113 pattern is canonical).
6. **Kind-enum plumbing macro** in `kinds.rs`: one `macro_rules! kind_str_plumbing { ... }` generating `as_str`/`Display`/`Serialize`/`Deserialize`/`FromStr` per enum from a single variant→string table; apply to ProtocolKind/TransportType/SecurityType/CoreType (their string tables move into the single source; `as_str_equals_protocol_display_strings` test at kinds.rs:437 pins this and must stay green). Also collapse `ProtocolKind::try_from_i32/to_i32` mirrored 27-arm tables onto the same table where the i32 mapping is contiguous-derived; if any arm's i32 is irregular, leave i32 tables hand-written (do not invent a formula).
7. **ProtoIdentity macro**: `macro_rules! proto_identity` generating compute_sig bodies (rapidhash init/tag/finish scaffolding ×20); compute_cred_hash stays as-is (already centralized in utils.rs).
8. **Canonical base64/percent decoders**: promote `leas-config/src/base64_util.rs::decode_base64` algorithm to `leas-proto/src/proto_spec/utils.rs` (keep the existing proto-side engine = plain `base64` crate + `urlencoding`, not `base64_simd` — proto has no simd dep; merge the percent-decode-first behavior from base64_util which proto currently lacks AFTER confirming proto consumers ss/ssr/vmess don't depend on missing it: their inputs come from RawUrlX which pre-splits and percent-decodes, so added percent-decode is a no-op there). Delete `base64_util.rs`; migrate its callers (`grep -rn "base64_util" crates --include='*.rs'` → only leas-config internal today; subscription.rs streaming decoder is separate machinery, untouched). Delete `import_export.rs:369 percent_decode` + `hex_val_sub` + `fix_percent_encoding` (:350) in favor of `urlencoding::decode` with the %25-repair folded into the new shared `percent_decode_str`. Keep `fast_perc.rs` (intentional hot-path SIMD specialization) and keep `coerce_bool` spellings exactly — do NOT migrate the strict `"1"|"true"|"True"` insecure parsers onto loose `coerce_bool` ("yes"/"on"/"y"/"n"/"off" spellings would change parse behavior; instead add `fn coerce_flag_str(s:&str)->Option<bool>` matching `"1"|"true"|"True"|"yes"` true / `"0"|"false"|"False"|"no"` false beside coerce_bool in utils.rs and migrate the 6 inline copies at anytls.rs:104, http_client.rs:121, hysteria1.rs:144, hysteria2.rs:152 + siblings).
9. Fresh-environment gate: `cargo build -p leas-proto && cargo nextest run -p leas-proto -p leas-config`.
